# Git: как начать коммитить (для новичка)
**Дата: 14.08.2026. Репозиторий — монорепо в C:\Traktor. Коммитишь ты, я даю готовые сообщения коммитов.**

## Идея (чтобы история была понятной)
1. Всё лежит в `C:\Traktor` — я кладу туда файлы, ты их коммитишь.
2. **Правило именования коммита** (одно на всех): `тип(область): что сделано`.
3. После каждого моего блока работы **я даю готовую строку коммита** — просто копируешь.
4. Секреты в репозиторий не попадают — уже настроен `.gitignore` (пароли, ключи, `*.tfvars`).

## Типы коммитов (запоминать не надо — я буду подставлять сам)
- `feat` — новая функциональность (экран, сервис, эндпоинт)
- `fix` — исправление
- `docs` — документы (ТЗ, план, README)
- `chore` — рутина (структура, конфиги, зависимости)
- `refactor` — переработка без смены поведения
- `test` — тесты

**Области:** `design-system`, `app`, `identity`, `gateway`, `contracts`, `infra`, `docs`, `brand`.

Примеры (так будет выглядеть история):
```
chore: инициализация проекта
feat(identity): OTP-вход, JWT ES256, /me
feat(gateway): проверка JWT по JWKS, rate-limit, прокси
feat(app): вертикаль входа на design_system
infra: Terraform для GCP и Cloudflare
```

## Шаг 1. Создай ПУСТОЙ репозиторий на GitHub
На github.com (в своей организации) → **New repository**:
- Имя: `traktor`
- **Private** (приватный)
- ⚠️ НЕ ставь галочки «Add README», «Add .gitignore», «Choose a license» — у нас они уже есть локально, иначе будет конфликт.
- Create repository. Скопируй адрес вида `https://github.com/ТВОЯ-ОРГ/traktor.git`.

## Шаг 2. Подключи папку C:\Traktor — вариант А (GitHub Desktop, рекомендую)
1. Открой **GitHub Desktop** → меню **File → Add local repository**.
2. Укажи папку `C:\Traktor`. Если скажет «this directory does not appear to be a Git repository» → жми **create a repository** (или «Initialize a Git repository here»).
3. Появится список всех файлов. Внизу слева в поле **Summary** впиши:
   ```
   chore: инициализация проекта (ТЗ, архитектура, прототип, каркас Фазы 2)
   ```
4. Жми **Commit to main**.
5. Вверху жми **Publish repository** → выбери свою организацию, имя `traktor`, галочку **Keep this code private** оставь включённой → **Publish**.

Готово — код на GitHub. Дальше при каждом изменении: GitHub Desktop показывает изменённые файлы → вписываешь мой готовый текст в Summary → **Commit to main** → **Push origin** (кнопка вверху).

## Шаг 2. Вариант Б — командами (если любишь терминал)
В VS Code открой терминал (Terminal → New Terminal) в папке `C:\Traktor` и выполни по одной:
```bash
git init
git add .
git commit -m "chore: инициализация проекта (ТЗ, архитектура, прототип, каркас Фазы 2)"
git branch -M main
git remote add origin https://github.com/ТВОЯ-ОРГ/traktor.git
git push -u origin main
```
Если попросит логин — используй свой GitHub-аккаунт (пароль не подойдёт, откроется вход через браузер — это нормально).

Дальше при каждом изменении:
```bash
git add .
git commit -m "СЮДА мой готовый текст коммита"
git push
```

## Шаг 3. Проверь, что секреты НЕ попали
После первого коммита в списке файлов (GitHub Desktop или на сайте) **не должно быть**:
- файлов `*.tfvars` (только `*.tfvars.example` — норм),
- `*.pem`, `*-key.json`, `.env`.
Если увидишь такой файл в коммите — скажи мне, поправим `.gitignore` до пуша.

## Наш порядок работы дальше
- Я делаю блок → кладу файлы в `C:\Traktor` → **даю тебе строку коммита**.

- Так каждый коммит = один понятный шаг. Через месяц всё читается как дневник проекта.
