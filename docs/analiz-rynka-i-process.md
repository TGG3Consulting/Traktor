# Traktor — Анализ рынка и проектирование бизнес-процесса

*Аналитический отчёт • август 2026 • подготовлен для запуска MVP на Flutter (iOS + Android + Web)*

---

## 1. Суть продукта (как я её понял)

Двусторонний маркетплейс «заданий для техники»:

- **Исполнители** — владельцы любой техники (экскаваторы, тракторы, самосвалы, краны, манипуляторы, сельхозтехника и т.д.) регистрируются и указывают свой парк.
- **Заказчики** — публикуют задание с параметрами («выкопать траншею 100 м, грунт такой-то, адрес, сроки») и своей ценой.
- Два режима сделки:
  1. **Фикс-цена + отклики** — заказчик ставит цену, исполнители откликаются, заказчик выбирает.
  2. **Обратный аукцион** — заказчик ставит стартовую цену (напр. 100 000 драм) и дедлайн; исполнители торгуются вниз; по истечении времени система автоматически определяет лучшую ставку, но **заказчик вправе отказаться** — автовыбор не финален.

Это модель «Uber для техники» + ценовой механизм inDriver (пассажир называет цену, водители соглашаются или торгуются).

## 2. Рынок: цифры

- Мировой рынок аренды строительной техники ≈ **$130–140 млрд**, растёт на ~5,4% в год (CAGR до 2030+). Драйверы: дорогая техника, нежелание подрядчиков «замораживать» капитал, рост инфраструктурных проектов.
- Онлайн-проникновение всё ещё **низкое** — большинство сделок по звонку/знакомству. Это и есть окно возможностей для платформ.
- В Африке и Индии сегмент «tractor-on-demand» доказал спрос: 220+ млн мелких фермеров без доступа к механизации.

## 3. Удачные (и поучительные) старты

### 🟢 Hello Tractor (Нигерия/Кения) — «Uber для тракторов»
Соединяет мелких фермеров с владельцами тракторов. Владелец трактора зарабатывает через платформу **до $30 000 в год**. Ключевая находка — **booking-агенты**: живые люди в деревнях, которые собирают заявки фермеров без смартфонов. Урок: *в офлайновых отраслях нужен «мостик доверия», чисто цифровой продукт буксует*.

### 🟢 inDriver — обратный торг как ядро продукта
Пассажир называет цену, водитель принимает/контрит. 888+ городов, 48 стран. Почему сработало: обе стороны чувствуют **контроль над ценой**, торг культурно привычен на развивающихся рынках (это прямо про Армению и регион). Урок: *прозрачный торг > скрытый алгоритм ценообразования*.

### 🟢 EquipmentShare (США) — гигант сегмента
Начинали как P2P-шеринг техники подрядчиков, выросли в компанию с миллиардными оборотами, добавив телематику (датчики на технике) и собственный парк. Урок: *данные о технике и её занятости — вторая ценность платформы после сделок*.

### 🟢 Yard Club (США) — экзит в Caterpillar (2017)
P2P-аренда простаивающей техники между подрядчиками. Куплен Caterpillar — производителю нужны были данные и цифровой канал. Урок: *даже средний маркетплейс ценен для индустриальных гигантов = потенциальный экзит*.

### 🟡 DOZR (Канада) — рост и жёсткий урок
Маркетплейс-агрегатор аренды, $34 млн инвестиций, топ-рейтинги Deloitte — и **receivership (внешнее управление) в 2025**. Урок: *тонкая маржа агрегатора + дорогая логистика убивают юнит-экономику; комиссия должна покрывать реальные издержки сделки, расти «в ширину» без прибыли опасно*.

### 🟡 Trringo (Mahindra, Индия)
Аренда тракторов по звонку и через приложение, опора на сеть франчайзи-хабов. Урок: *гибрид «приложение + колл-центр/диспетчер» обязателен на старте — не все клиенты готовы к чисто цифровому флоу*.

### 🇷🇺 Россия/СНГ: Перевозка24, Спецшеринг, СтройТакси, Rentaller и др.
Топ-10 бирж работают в трёх моделях: (а) доска объявлений с открытыми контактами, (б) агрегатор с автоподбором исполнителя, (в) диспетчерская служба с гарантией подачи. Слабость почти всех — **сделка уходит в телефон**, платформа не контролирует оплату и не зарабатывает с транзакции. Урок: *если не держать сделку и оплату внутри — останешься бесплатной доской объявлений*.

## 4. Выводы для Traktor

1. **Механизм inDriver-торга — правильная ставка.** Для рынка Армении/СНГ торг естественен; ни одна местная биржа техники его нормально не реализовала. Это дифференциатор №1.
2. **Держать сделку внутри платформы.** Контакты открывать только после подтверждения сделки; оплата/предоплата через платформу (эскроу) — иначе повторится судьба «досок объявлений».
3. **Не владеть техникой** (asset-light, как Dozr/Hello Tractor), но **верифицировать** исполнителей (документы на технику, фото, права оператора) — доверие решает.
4. **Гибридный онбординг**: на старте допускаем диспетчера/оператора, который помогает оформить заявку по телефону.
5. **Юнит-экономика с 1-го дня**: комиссия 5–10% со сделки (или сервисный сбор с заказчика), а не «потом придумаем».
6. **Начать с одного региона и 3–5 типов работ** (земляные работы, перевозка, кран/манипулятор) — глубина важнее ширины.

## 5. Бизнес-процесс (спроектированный)

### 5.1 Роли
- **Заказчик** (Client) — физлицо или компания с заданием.
- **Исполнитель** (Owner/Operator) — владелец техники; у одного аккаунта может быть несколько единиц техники и операторов.
- **Админ/Модератор** — верификация, споры, каталог типов техники.
- Один пользователь может быть и заказчиком, и исполнителем (переключение роли в профиле).

### 5.2 Регистрация и верификация
1. Регистрация по телефону (SMS-код) + имя; email опционально.
2. Заказчик может публиковать сразу (лёгкий вход).
3. Исполнитель добавляет технику: тип (из каталога), марка/модель, год, характеристики, фото, документы. Статус техники: `на проверке → одобрена / отклонена`.
4. Бейдж «Проверенный исполнитель» после проверки документов админом.

### 5.3 Создание задания
Параметры: тип работы, тип техники (или «предложите сами»), описание, объём (метры/тонны/часы), геолокация на карте, даты/сроки, фото места, бюджет, режим сделки:
- **Режим A: фикс-цена** — «сделаю за N» / отклики.
- **Режим B: обратный аукцион** — стартовая цена, дедлайн аукциона (напр. 24 ч), опц. шаг ставки, опц. резервная (минимально разумная) цена.

Статусы задания: `черновик → опубликовано → идёт торг → выбор исполнителя → подтверждено → в работе → выполнено (ожидает приёмки) → завершено / спор / отменено`.

### 5.4 Режим A — фикс-цена (полный цикл)
1. Заказчик публикует задание с ценой.
2. Подходящие исполнители получают push (фильтр по типу техники и радиусу).
3. Исполнитель: **«Принять цену»** или **«Предложить свою»** (контр-оффер, как в inDriver).
4. Заказчик видит список откликов (цена, рейтинг, техника, расстояние) → выбирает.
5. Взаимное подтверждение → контакты открываются, создаётся чат сделки.
6. Далее — общий блок «Исполнение и оплата» (5.6).

### 5.5 Режим B — обратный аукцион (полный цикл)
1. Заказчик публикует: стартовая цена 100 000 драм, дедлайн (напр. 24 ч).
2. Исполнители ставят ставки **вниз**; каждая новая лучшая ставка видна всем (анонимно: «Исполнитель №3, рейтинг 4,8 — 87 000»); участники получают push «вашу ставку перебили».
3. Правила честности: ставка = оферта (обязательство выполнить за эту цену); нельзя отозвать ставку в последние 2 часа; антиснайпинг — ставка в последние 5 минут продлевает аукцион на 10 минут.
4. **Дедлайн** → система выбирает лучшую ставку. «Лучшая» ≠ только самая низкая: рекомендуемый скоринг = цена (60%) + рейтинг (25%) + расстояние/соответствие техники (15%). Победитель получает статус «предварительно выбран».
5. **Окно решения заказчика (напр. 12 ч)**: заказчик может (а) подтвердить победителя, (б) выбрать вручную любую другую ставку, (в) **отказаться совсем** — без штрафа, задание закрывается или перезапускается. Автовыбор — рекомендация, не вердикт (как и задумано).
6. Если заказчик молчит всё окно — задание автоматически закрывается (защита исполнителей от «подвисших» аукционов).
7. Подтверждение → контакты, чат, далее 5.6.

### 5.6 Исполнение и оплата (общий блок)
1. **Фиксация сделки**: цена, объём, сроки — зафиксированы в карточке сделки.
2. Оплата (поэтапно по мере готовности платёжки): v1 — наличные/перевод напрямую, платформа фиксирует сумму; v2 — предоплата в эскроу на платформе (Idram/Telcell/карты для Армении), выплата исполнителю после приёмки, минус комиссия.
3. Исполнитель отмечает «Выехал» → «Начал работу» (гео-чекин) → «Завершил» + фото результата.
4. Заказчик принимает работу (окно 24–48 ч; молчание = автоприёмка).
5. Обоюдные **оценки и отзывы** (звёзды + текст). Рейтинг влияет на скоринг в будущих аукционах — мотивация качества.
6. **Спор**: любая сторона открывает диспут → модератор решает по фото/чату/гео-данным.
7. Отмены: заказчиком после подтверждения — помечается в профиле; исполнителем после подтверждения — штраф к рейтингу (борьба с «кинул и пропал»).

### 5.7 Монетизация (рекомендация)
- Фаза 1 (набор массы): всё бесплатно.
- Фаза 2: комиссия 5–8% со сделки (при эскроу) и/или сервисный сбор; подписка PRO для исполнителей (приоритет в выдаче, аналитика); продвижение заданий.

## 6. MVP на Flutter — план

### Состав MVP (фаза 1)
Регистрация по SMS • профили двух ролей • каталог техники + добавление своей • создание задания (оба режима) • лента заданий с фильтрами и картой • отклики/контр-офферы • обратный аукцион в реальном времени + автовыбор + окно отказа • чат сделки • статусы исполнения • рейтинги/отзывы • push-уведомления • админ-панель (веб) для верификации и споров.

За рамками MVP: онлайн-платежи/эскроу, телематика, страхование, мультиязычность (сразу закладываем arm/ru/en в архитектуру, включаем позже).

### Технологии
- **Flutter 3.x** — один код: iOS, Android, Web (+ у админки тоже Flutter Web или простая веб-панель).
- **Backend: Firebase** (Auth по SMS, Cloud Firestore — реалтайм-ставки аукциона «из коробки», Cloud Functions — автовыбор победителя по таймеру, FCM — push, Storage — фото). Альтернатива — Supabase (PostgreSQL), если захотим полный контроль над данными; для vibe-coding и скорости старта Firebase проще.
- Карты: Google Maps / Yandex Maps SDK.
- State management: Riverpod. Архитектура: feature-first, clean-ish.

### Этапы работы
1. **Неделя 1**: каркас проекта, дизайн-система, навигация, Auth по SMS, профили.
2. **Неделя 2**: каталог техники, создание задания, лента + карта, отклики (режим A).
3. **Неделя 3**: обратный аукцион (реалтайм-ставки, таймер, автовыбор, окно отказа), чат, push.
4. **Неделя 4**: статусы исполнения, рейтинги, админ-верификация, полировка, сборки iOS/Android/Web.

*(«Недели» — этапы, не календарные обещания: работаем итерациями, каждый этап вы получаете рабочую сборку.)*

## 7. Риски и как их закрываем

| Риск | Митигация |
|---|---|
| «Курица и яйцо» — нет исполнителей → нет заказчиков | Старт в одном регионе; ручной онбординг первых 30–50 владельцев техники до публичного запуска |
| Сделки уходят «в телефон» мимо платформы | Контакты после подтверждения; ценность внутри (рейтинг, гарантии, споры); позже эскроу |
| Демпинг и халтура в аукционе | Скоринг не только по цене; резервная цена; рейтинг-штрафы; верификация |
| Ставка-обман (поставил и пропал) | Ставка = оферта, штраф рейтинга за отказ победителя |
| Юнит-экономика (урок DOZR) | Не владеем техникой, не возим её; комиссия закладывается в модель с 1-го дня |
