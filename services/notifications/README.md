# notifications — сервис уведомлений

Реестр push-токенов устройств и рассылка уведомлений пользователю на все его
устройства. Часть Фазы 2 (каркас нотификаций, п. 4 плана). Полная push-матрица
(ТЗ §2.14: тихие часы, центр уведомлений, категории) — Фаза 5.

## Что делает

- **POST `/v1/devices`** (через gateway, Bearer + Idempotency-Key) — зарегистрировать
  push-токен текущего устройства. Идемпотентно по токену. Пользователь берётся из
  проверенного `X-User-Id`, который проставляет gateway (клиент подменить не может).
- **DELETE `/v1/devices/{token}`** (через gateway, Bearer) — снять регистрацию
  (logout / отзыв разрешения).
- **POST `/internal/notify`** (сервис-сервис, наружу не проксируется) — разослать
  уведомление на все устройства пользователя. Протухшие токены (провайдер вернул
  `UNREGISTERED`) удаляются на месте. Позже вызывается консьюмером Pub/Sub из outbox.
- **GET `/healthz`** — проба.

## Провайдер пушей (за интерфейсом, §2.3.14)

`internal/push.Provider` — абстракция транспорта. «Путь эвакуации»: FCM → APNs/
web-push без изменения вызывающего кода.

- **fake** (по умолчанию) — ничего не шлёт наружу, пишет в лог и запоминает
  сообщения; работает офлайн, без ключей. Токены с префиксом `invalid` считаются
  протухшими — так тестируется ветка очистки токенов.
- **fcm** — Firebase Cloud Messaging HTTP v1. Включается, когда задан
  `FCM_PROJECT_ID`. Авторизация — scoped access-token от metadata-сервера Cloud Run
  (сервисный аккаунт), **без файлов-ключей в репозитории** (§2.3.15). Из Firebase у
  нас только FCM (правило 17).

## Запуск (dev)

```bash
PORT=8082 go run ./cmd/notifications           # fake push
FCM_PROJECT_ID=traktor-xxxx PORT=8082 go run ./cmd/notifications   # реальный FCM (нужен Firebase-проект)
```

## Хранилище

- Дефолт — in-memory (`internal/store`, компилируется офлайн, для dev/тестов).
- Прод — Postgres (`//go:build postgres`), схема `notifications` (schema-per-service,
  §2.3.11), см. `migrations/0001_init.sql`. Cross-schema JOIN запрещён — связь с
  пользователем по `user_id`.

## Тесты

```bash
go vet ./... && go build ./... && go test ./...
```

Покрыто: регистрация/идемпотентность/снятие токена, рассылка на все устройства,
очистка протухшего токена, HTTP-флоу (401 без `X-User-Id`, 204 регистрация,
delivered при рассылке), формат запроса FCM v1 и маппинг протухшего токена.

## Зависит от Тиграна

Реальный FCM включается после заведения **Firebase-проекта** (Google-аккаунт):
`FCM_PROJECT_ID` + права `firebase.messaging` у сервисного аккаунта Cloud Run
(проставляется Terraform). До этого сервис работает на fake-провайдере.
