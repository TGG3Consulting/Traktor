## 2. КАК ВЫПОЛНЯТЬ КОМАНДЫ НА КОМПЬЮТЕРЕ (важно для следующей сессии)

У Claude нет прямого доступа к терминалу Windows: встроенный shell — изолированный
Linux без интернета и без Go. Поэтому работает такая схема, и она проверена:

1. Claude пишет нужные команды в `C:\Traktor\scripts\run.bat` (файловыми инструментами).
2. Запускает его двойным кликом в Проводнике (computer-use, доступ к Проводнику
   выдаётся один раз за сессию).
3. Скрипт пишет вывод в `C:\Traktor\scripts\_out\*.txt`, Claude читает файл.

Готовые скрипты (запускаются двойным кликом, результат — в `scripts\_out`):

| Скрипт | Что делает |
|---|---|
| `probe.bat` | что установлено: go, flutter, docker, git, node, состояние репозитория |
| `check-all.bat` | формат, сборка, vet, тесты и актуальность go.mod всех трёх сервисов |
| `pg-test.bat` | поднимает Postgres в Docker, гоняет интеграционные тесты БД, гасит контейнер |
| `smoke.ps1` (через `run.bat`) | поднимает три сервиса и проходит весь путь пользователя через шлюз |
| `install-go.ps1` | установка Go SDK без прав администратора (уже выполнена) |

⚠️ **Порты 8080–8082 на машине заняты** (Docker/WSL relay). Локальные запуски — на
18080–18082, иначе запросы уходят в чужой сервис и тесты «зеленеют» на пустых ответах.

## 4. ЧТО СДЕЛАНО (переписывание бэка, правило 23)

### services/identity
- JWT: самописный ES256 → **golang-jwt/jwt/v5**. Формат полезной нагрузки не изменился
  (`sub/iat/exp/roles/activeRole/typ`), клиенты совместимы. Алгоритм зафиксирован
  списком `ES256` — подмена алгоритма невозможна.
- JWKS: ручная сборка JSON → **lestrrat-go/jwx/v2** (документ собирается один раз на старте).
- Роутер: `net/http.ServeMux` → **chi/v5**; авторизация вынесена в middleware, claims
  кладутся в контекст.
- Хранилище: заглушка под build-тегом → **полная реализация на pgx/v5** без тегов.
  Телефоны шифруются (pgcrypto), поиск по `phone_hash`.
- Миграции: **golang-migrate**, файлы вшиты в бинарник (`go:embed`), накат при старте.
- Идентификаторы пользователей и семей токенов — **google/uuid** (совместимо с `uuid` в БД).
- `main.go`: `log/slog`, graceful shutdown, выбор хранилища по `DATABASE_URL`.

### services/gateway
- Проверка токенов: самописный разбор JWT и загрузка JWKS → **jwx `jwk.Cache`** +
  **golang-jwt**. При неизвестном `kid` набор ключей обновляется на месте (ротация ключа
  не роняет вход).
- Лимиты: самописный счётчик → **go-chi/httprate**. CORS → **go-chi/cors**. Роутер → **chi/v5**.
- Reverse-proxy переведён на современный `Rewrite` + `SetXForwarded` (клиент не может
  подделать `X-Forwarded-*`).
- `Idempotency-Key` пока проверяется на наличие; полноценное хранилище ответов в Redis —
  помечено `TODO` на шаге кэша.

### services/notifications
- FCM: ручной HTTP v1 и самописный кэш токена metadata-сервера → **официальный
  Firebase Admin SDK** (`firebase.google.com/go/v4`). Интерфейс `push.Provider` не изменился,
  fake-провайдер остался для dev.
- Роутер → **chi/v5**; хранилище → **pgx/v5** с миграциями; `main.go` — slog + graceful shutdown.

### Инфраструктура
- Dockerfile всех трёх: Go 1.25, отдельный слой зависимостей, `-trimpath -ldflags="-s -w"`,
  distroless. Упоминания «stdlib-only» убраны.
- CI: Go 1.25, кэш модулей, `go build`, `go vet`, `go test -race`, `go mod verify` и проверка,
  что `go mod tidy` не расходится с репозиторием.

### Найденные и исправленные баги
1. **Миграции notifications молча не накатывались:** оба сервиса писали версию схемы в одну
   таблицу `schema_migrations`, второй видел чужую версию и считал, что накатывать нечего.
   Теперь у каждого сервиса своя таблица версий.
2. **Гонка при обновлении refresh-токена:** пометка «использован» стала атомарной
   (`UPDATE ... WHERE used = false`), два одновременных запроса больше не выдадут две сессии.
3. Ошибка регистрации JWKS-кэша раньше молча проглатывалась — теперь шлюз падает на старте,
   а не отвергает все токены пользователей.

- `pg-test.bat`: реальный Postgres 16 в Docker — миграции, шифрование телефона (проверяется,

  вход, `/me`, отказ без токена, `PATCH /me`, регистрация push-токена (шлюз проставляет
  `X-User-Id`), доставка пуша, ротация refresh с сохранением роли, отказ при повторе старого
  refresh, выдача JWKS. Все зелёные.
